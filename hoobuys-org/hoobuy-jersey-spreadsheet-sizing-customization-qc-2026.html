HooBuy Jersey Spreadsheet: Sizing, Customization and QC

Published and fact-checked: September 7, 2026

Independent-site disclosure: hoobuys.org is not HooBuy. A spreadsheet row records product-discovery evidence; it does not prove current stock, fit, customization accuracy, authenticity, quality or return eligibility. Reopen the exact listing and selected state before ordering.

A HooBuy jersey spreadsheet needs a different structure from a general clothing list. A jersey can have a base edition, sleeve type, player or blank option, name, number, badge set and fit label that combine into one selected variant. A row that says only “blue, size L” may point to the wrong product even when the thumbnail looks right.

The useful record separates source identity, original option wording, sizing evidence, customization instructions and later QC results. It also preserves unknowns. This guide shows the fields that let a product-discovery user compare candidates without turning seller claims or borrowed photos into guarantees.

Create an identity key before recording style

Open the final destination listing and save the original source URL, resolved URL, marketplace, product ID, seller or shop ID, displayed title and verification date. Add the exact image fingerprint only as a matching aid. An image is not a stable identifier.

Use the product-link verification workflow if the URL redirects, opens a generic page or changes seller. When the product or seller ID changes, create a new candidate row. Do not overwrite the old identity because the replacement looks similar.

Preserve option grammar exactly

Do not translate or normalize the source options in the evidence column. Store the original label for color, size, player or blank version, sleeve, patches, name and number. Put a reader-friendly interpretation in a separate field. This makes it possible to copy the correct choice later and detect ambiguous option combinations.

If one menu bundles several decisions, save the full displayed string and parse its parts into separate columns. If personalization is entered into a text box or order note rather than a menu, record that workflow. Never assume a preview image proves what will be submitted.

Split base product from customization

Create a base identity group and a customization group. The base group covers garment edition, color, collar, sleeve, panel design and default badge state. The customization group covers exact name characters, number digits, location, font or style label, patch selection and any seller instruction.

Preserve capitalization, spaces, punctuation and diacritics. Add a character count and a second-person verification field for important text. If the seller restricts characters or has no visible confirmation method, mark that as a decision risk rather than shortening the request silently.

Build a size-chart evidence block

Copy the source size labels and every measurement exactly as displayed, including unit, measurement name, garment or body basis, tolerance note and chart date. Save the chart image or text reference privately if allowed, but keep the structured values in the spreadsheet so candidates can be compared.

Do not convert labels such as M, L or XL into a universal scale. Do not merge chest circumference with garment width. If the chart lists a flat half-chest measurement, keep it as such. If the method is unclear, write “method not stated” and request clarification before relying on the number.

Compare with a real reference garment

Measure a jersey that already fits the intended wearer. Lay it flat without stretching. Record the same endpoints as the candidate chart: chest width, body length and sleeve path. Use one tape and repeat any high-consequence measurement.

Store the reference garment, date and method. Compare dimension by dimension rather than choosing a size from height and weight alone. A body measurement and a finished-garment measurement answer different questions. The spreadsheet should make the difference visible.

Keep seller claims in their own columns

Record material, construction, print, embroidery, fit and weight statements as seller claims with the exact wording and verification date. Do not upgrade “polyester,” “stitched” or “player version” into an independently confirmed specification. Listing photos may illustrate the claim, but they do not test fiber content or durability.

Add a source confidence field: displayed in selected variant, displayed generally, visible only in an image, or absent. This prevents one broad description from being applied to every option.

Design QC questions before ordering

A strong row predicts what later warehouse evidence must answer. Create QC fields for full front and back identity, size tag, name spelling, number digits, patches, color-block layout, collar, sleeve details, visible stitching and measurement requests. State the exact view or endpoints required.

This is different from performing the final photo review. The spreadsheet plans questions; the warehouse record later supplies evidence. Do not fill QC fields with listing images. Use a status such as not requested, pending, confirmed, conflict or cannot determine.

Handle personalization as a return-risk flag

Customized goods may have different seller rules or after-sale options. The spreadsheet should never promise that a personalized jersey can be returned. Add fields for the current seller statement, confirmation step, production status if shown, and the latest point at which changes appear possible.

If eligibility is not visible, mark it unknown. A spelling confirmation and a clear QC plan reduce preventable mistakes, but they do not create a return right. Keep the current platform and seller instructions with the order record.

Record price as a selected-state observation

Save the displayed product price only after selecting the intended base options and customization. Record quantity, currency, domestic freight state, any customization amount and timestamp separately. A minimum thumbnail price may belong to a blank or different version.

Do not insert international shipping into the product-price cell. If the listing provides weight, record the value, option scope and source as an estimate. Final packed cost depends on the later parcel, route and packaging state.

Worked example: one title, three products

A listing title describes a 2026 jersey. The options include blank short sleeve, player-name short sleeve and long sleeve with patches. The selected price changes, but the thumbnail does not. A one-cell record would hide three materially different products.

Create separate candidate rows or a parent row with three versioned selections. Each must store its full option string, size chart, personalization state, selected price and QC request. Reject any row whose edition or patch choice cannot be matched to the intended order.

Use explicit stop conditions

  • Final URL does not resolve to the intended product.
  • Seller or product ID cannot be matched.
  • The required edition, color, sleeve or size is missing.
  • Personalization text cannot be confirmed exactly.
  • Size-chart measurement method is incompatible with the reference.
  • A critical seller claim has no source.
  • Selected-state price or quantity cannot be reproduced.
  • Return eligibility is assumed rather than checked.

Freeze the pre-order snapshot

Before ordering, save the final row version and check every selected field against the live listing. After payment, append the order ID and confirmed choice without changing the original snapshot. If the seller contacts the buyer about an option, keep the message outcome as a dated event.

Later, attach warehouse identity and QC results to the same version. If the evidence points to a different edition or customization, record a conflict. Do not edit the planned value to match what arrived.

Run a final jersey-row audit

  1. Source, product and seller identities are reproducible.
  2. Edition and every option label are preserved verbatim.
  3. Name, number and patches have separate confirmation fields.
  4. Original size-chart units and methods are retained.
  5. Reference-garment comparisons use matching endpoints.
  6. Seller claims remain labeled as claims.
  7. Selected price and weight have scope and date.
  8. QC questions are written before warehouse arrival.
  9. Unknowns and stop conditions remain visible.

Maintain evidence instead of a link dump

A HooBuy jersey product find becomes useful when another reader can reproduce the selected product, understand the sizing method and know which customization details still need proof. That requires more than saving a URL.

Keep identity, original option grammar, measurements, claims, price and later QC in separate fields. Preserve each decision state instead of overwriting it. The result is a jersey spreadsheet that can support ordering and review without pretending that a listing alone guarantees fit, personalization or quality.
