Hoobuy Order Tracking Spreadsheet: A Handoff Ledger That Stays Useful

Published and checked: August 13, 2026

Purpose: this is a private order-management worksheet, not a public product-find spreadsheet. It records what happened between a purchase instruction, seller dispatch, domestic courier, warehouse intake, QC and parcel submission. Do not enter passwords, full payment details or unnecessary personal information.

A normal order page tells you the current label. A useful tracking spreadsheet tells you what evidence supports that label, which party is expected to act next, and what changed since the previous check. That distinction becomes important when one marketplace purchase splits into several domestic parcels, a courier marks a parcel delivered before warehouse intake appears, or several warehouse item IDs are created from one incoming package.

The worksheet below is designed around handoffs rather than promised deadlines. Hoobuy's public help material separates shopping, delivery, warehouse, inspection and storage into different service areas. Its forwarding guide also emphasizes domestic tracking numbers and generated forwarding order IDs. Those public steps support keeping the identifiers separate. The column design and escalation method are independent editorial recommendations.

One row should represent one expected item

Do not make one row represent an entire haul when the items can move independently. The useful unit is an expected item linked to its source and selected variant. One seller order can contain three items; a seller can dispatch them in two boxes; the warehouse can later assign three item IDs. If the row begins with “whole order,” those relationships become difficult to describe.

Create a stable record ID such as HB-2026-001. It is your private reference, not a platform identifier. Never change it when a status changes. Put official or marketplace identifiers in their own columns. This prevents a forwarding order ID from replacing a domestic tracking number, or a warehouse item ID from replacing the original source record.

The eight field groups that matter

1. Source identityPrivate record ID, source URL, live listing title and seller or marketplace reference.
2. Purchase instructionExact colour, size, model, quantity and any buyer note needed to identify the selection.
3. Order identityAgent order ID, or forwarding order ID when the goods were purchased separately.
4. Domestic movementCourier company, tracking number, package count and the last carrier event.
5. Warehouse receiptReceipt date, warehouse item ID and whether the expected quantity was matched.
6. QC decisionVisible identity, variant, quantity, condition, measurements and any precise missing evidence.
7. Parcel handoffConsolidation group, packaging choice, route check and parcel ID after submission.
8. Next actionOne owner, one requested outcome and a UTC timestamp for the next review.

A timestamp matters because “still waiting” has no starting point. Use one consistent format, preferably UTC, and keep a separate status-history tab if you need more than the latest event. Do not continuously overwrite the last verified event. A short history—label created, carrier accepted, delivered, warehouse matched—can show exactly where a handoff stopped.

How to record purchase and seller dispatch

At purchase, save the source URL and the exact selected option. Product pages can change after the order is placed, so write the variant in plain language instead of relying only on a later screenshot. If the seller requests a different amount or substitutes an option, add a dated note; do not silently change the original instruction.

For seller dispatch, separate a tracking number from carrier acceptance. A seller can provide a number before the carrier has the parcel. Put the number in the tracking column, then record the last verified carrier event separately. This lets you distinguish “number exists,” “carrier accepted,” “in transit” and “delivered.” If the seller splits the order, duplicate the necessary source fields and give each physical package its own courier entry.

How to record forwarding orders

A forwarding order begins after you or another sender already purchased the goods. Hoobuy's public forwarding guide instructs users to obtain the current warehouse address, provide it to the sender, enter the domestic tracking number and save the generated forwarding order ID. Keep all of those layers.

Enter one row for every expected item, then connect it to the correct incoming package. When one courier number covers several items, repeat the courier number in those item rows or use a separate Packages tab and a lookup key. If several courier numbers exist, do not place them in one cell separated by commas. Separate rows make missing-package checks and support messages much clearer.

The public guide notes that numerous or large items may be photographed and stored separately, creating multiple item records. Add later warehouse IDs without deleting the forwarding ID or courier number. The worksheet should show the relationship: source item → physical domestic package → forwarding record → warehouse item.

Turn QC into an answerable decision

“QC passed” is too vague for a reusable record. Use small fields: identity matched, selected variant matched, quantity matched, visible condition acceptable, measurements checked, and missing evidence. Category notes should be concrete. Shoes may require model, size label, outsole and pair symmetry. Clothing may require size label, width, length, print placement and visible stitching. Accessories may require dimensions, included pieces and hardware.

QC photos show only visible evidence. They cannot establish authenticity, hidden construction, durability or fit. If a needed detail is missing, write one precise request in the next-action field, such as “straight-on size-label image” or “chest width with tape visible.” Check the live account for availability and price before requesting an extra service; the worksheet should not assume a universal free-photo count or fee.

Use the owner and next-action columns to stop duplicate follow-ups

Every unresolved row needs one current owner: buyer, purchasing agent, seller, domestic carrier, warehouse intake, QC or parcel team. Then write one expected outcome. “Check order” is not useful. “Confirm whether courier number X is matched to forwarding ID Y” identifies both the missing handoff and the evidence required.

Privacy and maintenance rules

  • Do not store passwords, card numbers, wallet credentials, identity documents or full home addresses.
  • Use limited sharing permissions. A support export should contain only the rows relevant to that issue.
  • Preserve the original source and selection; add dated changes instead of rewriting history.
  • Check active rows on a consistent schedule, but do not manufacture a universal deadline.
  • Archive completed rows rather than deleting them. They can help explain repeat purchases and seller package patterns.
  • Re-check live service rules, warehouse instructions and route information before acting on an old row.

A spreadsheet is useful only when it narrows the next question

The goal is not to collect every screenshot. It is to preserve enough evidence to identify the last completed handoff and the next missing one. Source and variant fields explain what should have been purchased. Carrier fields explain whether a physical package moved. Warehouse and QC fields explain what was received and what can be seen. Parcel fields begin only after the item decision is complete.

Use the downloadable template as a starting point, then remove columns you genuinely do not need. The strongest record is compact, consistent and safe to share in part. For a deeper explanation of each status, continue with the order-status guide. For self-purchased Taobao or Weidian goods, use the forwarding-order guide.
