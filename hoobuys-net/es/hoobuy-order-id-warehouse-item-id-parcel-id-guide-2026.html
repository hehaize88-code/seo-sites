ID de pedido frente a ID de artículo de almacén e ID de paquete en Hoobuy

Publicado: 11 de septiembre de 2026

Aviso de sitio independiente: hoobuys.net es una guía independiente de procesos y no es HooBuy. Las etiquetas de la interfaz, los mensajes de vendedores, los procedimientos del almacén y las políticas pueden cambiar. Verifica el registro actual del pedido y las condiciones oficiales vigentes antes de actuar.

El ID de pedido de Hoobuy, el ID de artículo de almacén y el ID de paquete pueden referirse a las mismas mercancías en etapas distintas, pero no son intercambiables. El ID de pedido organiza la compra y la comunicación con el vendedor. Un ID de artículo de almacén representa algo registrado después de la recepción. Un ID de paquete agrupa artículos de almacén seleccionados para su embalaje y envío internacional. Después, los números de transportista informan del movimiento físico fuera de esos registros de cuenta.

Mezclar estos identificadores es una de las formas más fáciles de crear una solicitud de asistencia poco sólida. Esta guía construye una cadena de identidad desde la selección del producto hasta la recepción en almacén y la expedición del paquete, para que cada estado, foto, mensaje y evento de seguimiento pueda vincularse al objeto correcto.

Trata el ID de pedido como la referencia de compra

Registra el ID de pedido cuando se cree o confirme la instrucción de compra. Añade el anuncio de origen, la opción seleccionada, la cantidad, el vendedor y cualquier nota del pedido. Las preguntas del vendedor, cambios de precio, compras fallidas, cancelaciones e información de expedición nacional deben seguir vinculados a esta referencia.

Un ID de pedido demuestra que existe un registro en la cuenta; no demuestra que un vendedor haya enviado un paquete. Cuando aparezca un número nacional, añádelo como registro dependiente. Si el vendedor divide el pedido, conecta cada número con el mismo pedido y asigna una fila independiente a cada paquete físico.

Trata el ID de artículo de almacén como la referencia de recepción

Tras la recepción y el registro, el sistema puede crear registros por artículo. Conecta cada ID de artículo de almacén con el pedido original, la variante exacta, la cantidad prevista y el paquete nacional. Verifica el título y la opción visibles, porque los productos similares de pedidos distintos pueden ser difíciles de distinguir después.

El registro del artículo es el lugar adecuado para adjuntar el estado del almacén, las pruebas visibles de inspección, las observaciones sobre cantidad y las decisiones posventa. No sustituye al historial del vendedor o del transportista. Conservar ambos niveles permite demostrar que un paquete entregado generó un registro de artículo incorrecto o que un artículo esperado nunca apareció.

Trata el ID de paquete como la referencia de embalaje

Cuando se seleccionan artículos almacenados para el envío internacional, el ID de paquete pasa a agrupar esa solicitud. Vincula cada ID de artículo de almacén incluido, instrucción de embalaje, ruta seleccionada y estado del paquete mostrado. Conserva qué artículos se excluyeron o quedaron almacenados; de lo contrario, un artículo ausente puede confundirse con un error de embalaje.

Cuando aparezca un número de seguimiento internacional, debe vincularse bajo el ID de paquete. El ID de paquete abre el registro de la cuenta, mientras que el número del transportista abre las pruebas de movimiento. Incluye ambos al preguntar por la expedición, la aceptación, un traspaso de ruta o la entrega.

Traza la cadena de identidad antes de investigar una discrepancia

  1. Anuncio de origen y variante seleccionada.
  2. ID de pedido y acción del vendedor.
  3. Número o números de los paquetes nacionales.
  4. ID o ID de artículos de almacén creados tras la recepción.
  5. ID de paquete que contiene los artículos seleccionados.
  6. Número internacional y cualquier número documentado del transportista de destino.

Una cadena completa puede ramificarse. Un pedido puede tener varios paquetes nacionales. Un paquete puede contener varios artículos. Varios artículos de almacén pueden entrar en un paquete internacional. Tu registro debe permitir esos vínculos en lugar de imponer un único número lineal al proceso.

Utiliza campos de registros principales y dependientes en el registro

En cada fila, etiqueta el tipo de objeto y su registro principal. El registro principal de un paquete nacional puede ser un pedido. Los registros principales de un artículo de almacén pueden incluir tanto el pedido como el paquete nacional. Los registros dependientes de un paquete son los artículos de almacén incluidos. Esta pequeña decisión de modelo de datos evita sobrescrituras accidentales y hace útiles los filtros.

Añade el sistema de origen, la etiqueta exacta, la hora de creación, el estado actual y el último evento verificado. Si cambia un identificador, conserva el valor antiguo con una nota que indique que ha sido sustituido. No pegues direcciones privadas ni datos de pago en el registro. Los identificadores y las pruebas de eventos suelen bastar para la conciliación.

Resuelve los identificadores repetidos o ausentes

Un número aparece en dos pedidos

Compara el vendedor, el artículo, la variante y los eventos de expedición. Conserva ambas vistas de la cuenta y pregunta si el número se comparte legítimamente o se ha asignado de forma incorrecta. No fusiones los pedidos por tu cuenta.

Un artículo de almacén no tiene paquete nacional de origen

Busca la lista de contenido del paquete entregado y las variantes del pedido. Solicita que se confirme el vínculo entre recepción y pedido antes de añadir el artículo a un paquete.

La lista de contenido de un paquete difiere de los artículos seleccionados

Guarda el registro de selección y el contenido mostrado del paquete. Identifica el ID exacto del artículo ausente o adicional y solicita comprobar el registro de embalaje.

Un número de transportista no tiene vínculo con un paquete

Verifica el número en los detalles del paquete y en el registro de la ruta. Un número encontrado en una notificación sin relación no basta para establecer su identidad.

Elige el identificador correcto para cada solicitud de asistencia

  • Problema de compra o de vendedor: empieza por el ID de pedido.
  • Entregado pero no almacenado: empieza por el número nacional y el pedido esperado y después enumera los ID de artículos que faltan.
  • Problema de identidad o cantidad en almacén: empieza por el ID de artículo de almacén y sus registros de pedido y paquete de origen.
  • Problema de embalaje: empieza por el ID de paquete y los ID de artículos incluidos.
  • Problema de movimiento internacional: empieza por el ID de paquete junto con el número correcto del transportista.

Incluye la cadena mínima de registros principales y dependientes necesaria para demostrar la discrepancia. Enviar todos los identificadores de la cuenta sin etiquetas obliga al lector a reconstruir el modelo y aumenta la probabilidad de investigar el objeto equivocado.

Revisa la cadena en tres momentos de decisión

Después de la expedición del vendedor, verifica que cada número nacional esté vinculado al pedido previsto. Después de la recepción en almacén, verifica que cada ID de artículo corresponda a la variante y al paquete esperados. Antes de solicitar el envío del paquete, verifica que contenga los ID de artículos previstos y ninguna incidencia de almacén pendiente. Tras la expedición, conecta el número internacional al paquete correcto.

Estas comprobaciones son más rápidas que reconstruir la cadena después de una discrepancia. También ayudan a decidir si un problema pertenece a la compra, la entrega nacional, la recepción, el embalaje o un traspaso de transportista.

Utiliza las guías internas en la etapa que cubren

La guía del vendedor al almacén se centra en la custodia nacional. La guía de recepción cubre los paquetes entregados sin registros de artículos. La guía de números de seguimiento separa el movimiento nacional del internacional. Para un registro ordenable, utiliza la hoja CSV privada.

Cada recurso responde a una pregunta distinta. Utiliza esta guía de identificadores cuando la principal dificultad sea saber qué registro pertenece a cada etapa.

Mantén un registro de incidencias cuando se rompa la cadena

Añade una nota independiente por cada vínculo roto: la fecha de detección, los dos registros que deberían conectarse, las pruebas comprobadas, la solicitud enviada y la corrección final. No modifiques los campos principales de identificadores mientras el caso siga abierto. Un registro de incidencias conserva los datos originales y deja claro qué vínculo sigue necesitando respuesta.

Cuando se resuelva el problema, registra quién o qué estableció el vínculo: una etiqueta corregida de la cuenta, un evento del transportista, una recepción en almacén o una confirmación de asistencia. Esto es más fiable que editar silenciosamente la hoja de cálculo hasta que parezca completa.

Cierra cada brecha restaurando un vínculo

Los problemas de identificadores se resuelven cuando se establece un vínculo principal-dependiente ausente: un pedido se conecta al paquete nacional correcto, una entrega al artículo de almacén correcto, los artículos seleccionados al paquete correcto o un paquete a su registro de transportista. Guarda el mensaje o evento que lo resuelve con su fecha y hora.

El objetivo no es reunir el mayor número de ID, sino mantener un mapa pequeño y preciso de las mercancías. Cuando cada identificador tiene una función y un registro principal, es más fácil interpretar el estado del pedido y las pruebas de asistencia son más breves, seguras y útiles para actuar.

Continúa con un enlace de producto verificado

Una vez resuelta la incidencia del proceso, abre el índice de productos y verifica el anuncio exacto, la opción y el destino actual antes de pedir.
