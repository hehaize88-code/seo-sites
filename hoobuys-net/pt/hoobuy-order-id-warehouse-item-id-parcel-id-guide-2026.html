Hoobuy: ID do pedido, ID do item no armazém e ID do pacote

Publicado: 11 de setembro de 2026

Aviso de site independente: A hoobuys.net é um guia independente de processos e não é a HooBuy. Rótulos da interface, mensagens de vendedores, procedimentos do armazém e políticas podem mudar. Verifique o pedido atual e os termos oficiais vigentes antes de agir.

O ID do pedido Hoobuy, ID do item no armazém e ID do pacote podem se referir às mesmas mercadorias em etapas diferentes, mas não são intercambiáveis. O ID do pedido organiza a compra e a comunicação com o vendedor. O ID do item representa algo registrado após o recebimento. O ID do pacote agrupa itens selecionados para embalagem e envio internacional. Os códigos das transportadoras então relatam o movimento físico fora desses registros da conta.

Misturar esses identificadores é uma das maneiras mais fáceis de criar uma solicitação fraca ao suporte. Este guia constrói uma cadeia de identidade da seleção de produtos ao recebimento e despacho do pacote, para que cada status, foto, mensagem e evento de rastreamento se associe ao objeto correto.

Trate o ID do pedido como referência central da compra

Registre o ID quando a instrução de compra for criada ou confirmada. Vincule anúncio original, opção escolhida, quantidade, vendedor e notas. Perguntas do vendedor, mudanças de preço, falhas de compra, cancelamentos e despacho doméstico devem permanecer vinculados a essa referência.

Um ID comprova a existência de um registro na conta; não comprova o despacho pelo vendedor. Quando surgir um código doméstico, adicione-o como registro subordinado. Se o vendedor dividir o pedido, conecte todos os códigos ao mesmo pedido, dando uma linha separada a cada pacote físico.

Trate o ID do item no armazém como referência central do recebimento

Após receber e cadastrar, o sistema pode criar registros por item. Conecte cada ID ao pedido original, variante exata, quantidade esperada e pacote doméstico. Verifique título e opção visíveis, pois produtos semelhantes de pedidos diferentes podem ser difíceis de distinguir depois.

O registro do item é o local correto para anexar status no armazém, evidências visíveis de inspeção, observações de quantidade e decisões de pós-venda. Não substitui o histórico do vendedor ou transportadora. Manter ambas as camadas permite mostrar que um pacote entregue gerou o registro errado ou que um item esperado nunca apareceu.

Trate o ID do pacote como referência central da embalagem

Quando itens armazenados são selecionados para envio internacional, o ID do pacote reúne essa solicitação. Vincule cada ID incluído, instrução de embalagem, rota escolhida e status exibido. Preserve quais itens foram excluídos ou ficaram armazenados; caso contrário, um item ausente pode ser confundido com erro de embalagem.

Vincule o código internacional ao ID do pacote quando aparecer. O ID abre o registro da conta, enquanto o código da transportadora abre evidências de movimentação. Inclua ambos ao perguntar sobre despacho, aceitação, transferência de rota ou entrega.

Mapeie a cadeia de identidade antes de investigar uma divergência

  1. Anúncio original e variante escolhida.
  2. ID do pedido e ação do vendedor.
  3. Código ou códigos de pacotes domésticos.
  4. ID ou IDs de itens criados no recebimento.
  5. ID do pacote com itens selecionados.
  6. Código internacional e eventual código documentado da transportadora de destino.

Uma cadeia completa pode ramificar. Um pedido pode ter vários pacotes domésticos. Um pacote pode conter vários itens. Vários itens do armazém podem entrar em um pacote internacional. Seu registro deve permitir essas relações, em vez de forçar um único número linear ao processo.

Use campos de registros principais e subordinados

Em cada linha, identifique o tipo de objeto e seu registro principal. O principal de um pacote doméstico pode ser um pedido. Os principais de um item podem incluir pedido e pacote doméstico. Os subordinados de um pacote são os itens incluídos. Essa pequena decisão de modelo de dados evita sobrescritas acidentais e torna filtros úteis.

Adicione sistema de origem, rótulo exato, hora de criação, status atual e último evento verificado. Se um identificador mudar, mantenha o antigo com uma nota de substituição. Não cole endereços privados ou dados de pagamento no registro. Identificadores e evidências de eventos costumam bastar para conciliar.

Resolva identificadores repetidos ou ausentes

Um código aparece em dois pedidos

Compare vendedor, item, variante e eventos de despacho. Preserve ambas as telas e pergunte se o código é compartilhado legitimamente ou atribuído incorretamente. Não una os pedidos por conta própria.

Um item não tem pacote doméstico principal

Pesquise o manifesto do pacote entregue e as variantes dos pedidos. Peça confirmação da ligação entre recebimento e pedido antes de incluir o item em um pacote.

O manifesto difere dos itens selecionados

Salve o registro de seleção e o conteúdo exibido. Nomeie o ID exato ausente ou extra e peça verificação do registro de embalagem.

Um código de transportadora não tem ligação com pacote

Verifique o código nos detalhes do pacote e no registro da rota. Um código encontrado em notificação não relacionada não basta para estabelecer identidade.

Escolha o identificador correto para cada solicitação

  • Problema de compra ou vendedor: comece pelo ID do pedido.
  • Entregue, mas não armazenado: comece pelo código doméstico e pedido esperado e liste os IDs de itens ausentes.
  • Problema de identidade ou quantidade no armazém: comece pelo ID do item e seus registros principais de pedido e pacote.
  • Problema de embalagem: comece pelo ID do pacote e IDs dos itens incluídos.
  • Problema de movimentação internacional: comece pelo ID do pacote e código correto da transportadora.

Inclua a menor cadeia de registros necessária para comprovar a divergência. Enviar todos os identificadores da conta sem rótulos obriga o leitor a reconstruir o modelo e aumenta a chance de investigar o objeto errado.

Audite a cadeia em três pontos de decisão

Após o despacho do vendedor, confira se cada código doméstico está no pedido correto. Após o recebimento, confira se cada ID de item corresponde à variante e ao pacote esperados. Antes de solicitar o envio, verifique se o pacote contém os IDs desejados e nenhuma exceção pendente no armazém. Após o despacho, conecte o código internacional ao pacote correto.

Essas verificações são mais rápidas que reconstruir a cadeia após uma divergência. Também ajudam a decidir se o problema pertence à compra, entrega doméstica, recebimento, embalagem ou transferência à transportadora.

Use os guias internos na etapa que abordam

O guia do vendedor ao armazém foca na custódia doméstica. O guia de recebimento aborda pacotes entregues sem registros de itens. O guia de códigos de rastreamento separa movimentação doméstica e internacional. Para um registro classificável, use a planilha CSV privada.

Cada recurso responde a uma pergunta diferente. Use este guia de identificadores quando a principal dificuldade for saber qual registro pertence a qual etapa.

Mantenha um registro de exceções quando a cadeia se romper

Adicione uma nota separada para cada ligação rompida: data em que foi encontrada, dois registros que deveriam se conectar, evidências verificadas, solicitação enviada e correção posterior. Não altere os campos centrais de identificação enquanto o caso estiver pendente. Um registro de exceções preserva os dados originais e deixa claro qual ligação ainda precisa de resposta.

Quando o problema for resolvido, registre quem ou o que estabeleceu a ligação — um rótulo corrigido na conta, evento da transportadora, recebimento no armazém ou confirmação do suporte. Isso é mais confiável que editar silenciosamente a planilha até ela parecer completa.

Feche cada lacuna restaurando uma ligação

Problemas de identificadores são resolvidos quando se estabelece uma ligação ausente: pedido ao pacote doméstico correto, entrega ao item correto do armazém, itens selecionados ao pacote correto ou pacote ao registro da transportadora. Salve a mensagem ou evento que resolveu o caso com horário.

O objetivo não é coletar o maior número de IDs. É manter um mapa pequeno e preciso das mercadorias. Quando cada identificador tem função e registro principal, o status se torna mais fácil de interpretar e as evidências para o suporte ficam mais curtas, seguras e acionáveis.
